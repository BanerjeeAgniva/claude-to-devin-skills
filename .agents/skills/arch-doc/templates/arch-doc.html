Reality check before you read any design doc.
  1. The solver that runs is BalancedBfsAssignmentServiceImpl, not CP-SAT. The one injection point is GridReplanServiceImpl:59.
  2. Adjacency is always the H3 1-ring (gridDisk(h,1)). The OSRM-based loader is never called.
  3. APPROVED rows are the live plan. There is no apply step; approving flips da_hex_assignment.status in place.

2 · Serviceability: can this parcel go there?

businessEvery booking asks the grid whether both pickup and drop fall on active hexes, and whether they are in the same city. The answer decides SAME_CITY versus INTERCITY pricing and routing.

Proposal lifecycle

Approval flips rows in place; nothing is copied or applied. If nothing is approved by 07:00, yesterday's plan is copied forward.
